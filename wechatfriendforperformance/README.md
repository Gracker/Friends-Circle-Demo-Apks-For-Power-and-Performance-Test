# 朋友圈性能测试模块

本模块是专门为测试Android滑动性能而设计的，通过模拟不同负载级别，提供了一个研究和优化Android UI性能的平台。

*Read this in [English](README_EN.md)*

## 功能特点

- **多层次负载测试**：
  - **单一负载模式**：轻负载、中负载、高负载
  - **混合负载模式**：模拟真实场景的复合型性能测试
    - 轻负载混合：doFrame任务强度1000 + 帧间任务强度2400
    - 中负载混合：doFrame任务强度2000 + 帧间任务强度1600  
    - 高负载混合：doFrame任务强度4000 + 帧间任务强度1067
  
- **精确控制**：
  - 使用固定种子的随机数生成器，确保每次测试的数据一致
  - 通过位置偏移量控制不同负载生成的评论和点赞数量
  
- **性能监控**：
  - 在关键代码处添加Trace点，方便使用Perfetto等工具进行性能分析
  - 支持滑动时的持续负载模拟，更接近真实使用场景

## 如何使用

1. 从主界面选择要测试的负载级别
2. 在滑动列表时观察UI性能表现
3. 使用Android Profiler或Perfetto收集性能数据
4. 分析结果并优化代码

## 实现细节

### 基础架构
- 使用RecyclerView高效显示列表内容
- 针对不同负载级别动态调整评论和点赞数量
- 滑动时控制图片加载，优化滑动体验
- 实现View对象缓存，减少View创建开销

### 统一配置中心

**LoadConfig 配置化管理**：
为了提高代码可维护性和调试便利性，所有负载参数统一在 `LoadConfig` 类中管理：

- **集中配置**：所有Activity的负载强度、任务间隔、随机种子统一配置
- **科学验证**：自动验证配置的科学性和一致性
- **易于调试**：一处修改，全局生效，方便性能调优实验
- **配置详情**：启动时自动输出配置信息到LogCat

### 混合负载架构设计

**科学原理**：
混合负载模式基于Android渲染机制的科学设计，将负载分为两个维度：

1. **doFrame负载**：模拟UI绘制期间的计算密集型任务
   - 在每个绘制帧内执行复杂数学运算、矩阵操作
   - 直接影响帧渲染时间，测试GPU和CPU协作性能
   - 强度递增：1000 → 2000 → 4000（几何级数增长，符合指数感知模型）

2. **帧间负载**：模拟UI空闲时间的后台处理任务
   - 在帧与帧之间执行图像处理、数据排序、字符串操作
   - 测试多线程和内存管理能力
   - 强度设计：2400 → 1600 → 1067（反比例衰减，平衡整体负载）

**任务调度机制**：
- **双调度器架构**：doFrame和帧间任务各自独立调度
- **固定随机间隔**：每1-5帧(16-83ms)执行一次任务，确保测试可重现性
- **负载平衡算法**：通过反比例关系平衡两种负载，总体性能压力呈线性递增

**科学依据**：
- 基于Weber-Fechner定律：人眼对性能变化的感知呈对数关系
- 遵循Android 60fps渲染管线：每帧16.67ms的时间预算
- 符合移动设备热力学模型：避免过热导致降频影响测试

## 性能测试方法

### 配置化测试流程
1. **查看配置**：启动应用，查看LogCat中的负载配置信息
2. **选择测试模式**：根据测试需求选择适当的负载级别
3. **调整参数**：如需微调，修改 `LoadConfig.java` 中的配置
4. **验证有效性**：配置变更后，系统会自动验证科学性

### 单一负载测试
适用于基础性能评估，测试特定场景下的性能表现

### 混合负载测试  
**推荐使用**，更接近真实应用场景：
1. **轻负载混合**：测试日常使用性能基线
2. **中负载混合**：测试中等压力下的性能稳定性
3. **高负载混合**：测试极限场景下的性能退化情况

### 测试数据分析
- **帧率指标**：监控FPS变化趋势，理想值≥55fps
- **帧时间分布**：分析doFrame vs 帧间任务的时间占比
- **内存占用**：观察不同负载下的内存使用模式
- **CPU使用率**：评估多核处理器的负载分配

## 优化建议

- 监控帧率和丢帧情况，识别性能瓶颈
- 优化列表项布局结构，减少过度绘制
- 控制滑动时的后台计算任务
- 使用异步加载机制减轻主线程负担
- **混合负载优化**：平衡doFrame和帧间任务的执行时机
